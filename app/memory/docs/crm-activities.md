# CRM Activities

CRM Activities is the **unified timeline** of every CRM-relevant event across accounts, leads, deals, and contacts. It merges two streams in one feed:

- **Human-logged entries** — Notes, Emails, Calls, Meetings that ops typed into the inline form
- **System-generated rows** — configurator saves, lot transitions, escrow placements, deal stage moves, automation fires, and other entity state-machine events

System rows carry a `SYSTEM` tag in the page subhead's legend. Everything else was logged by an admin. Open the page at **V3 CRM → Activities** (`/v3/crm/activities`).

## Page layout

- **Header** — page title, page subhead (with the `SYSTEM` tag callout), and a **+ Log Activity** button (top right)
- **Log form** (when opened) — three-field inline card: Kind, Description, Account
- **Filter bar** — kind pills with counts + counter on the right
- **Feed** — vertically stacked rows, one per activity, newest first
- **Banners** at the top — success / error feedback

## Activity kinds

Each activity has a **Kind** rendered as an icon chip on the left of the row. Filter pills (in order):

- **System** (lightning-bolt icon) — auto-generated by automations or entity state machines (rendered from the internal `SystemEvent` value with the label **System**)
- **Email** (envelope icon) — admin-logged email touchpoint
- **Call** (phone icon) — admin-logged call
- **Meeting** (users icon) — admin-logged meeting
- **Note** (pen icon) — admin-logged free-text note
- **Status** (right-left arrows icon) — entity state-machine transitions (e.g. a lot moved CLAIMED → SOURCED, a deal moved to a new stage). Rendered from the internal `StatusChange` value.

**Human kinds** — the ones ops can log by hand from this page — are Note, Email, Call, Meeting. **System** and **Status** rows are only created by the engine; they cannot be added or edited from here.

## Log a human activity

Use this to record a touchpoint that the system can't infer on its own.

1. Click **+ Log Activity** in the header. The inline form expands.
2. Fill the fields:
   - **Kind** — dropdown: `Note` / `Email` / `Call` / `Meeting` (default `Note`)
   - **Description** (required) — free text. Placeholder: *"Called CFO re: 24-mo term — sending firm offer tomorrow."*
   - **Account** (optional) — dropdown of accounts from **[CRM Accounts](/v3/crm/accounts)**. Default `— none —`. Linking to an account makes the activity show up in that account's drawer on the Accounts page.
3. Click **Log activity**.

Validation: *"A description is required to log an activity."* On success, a green banner reads `<Kind> logged — appended to the timeline and the Audit Log.` and the feed reloads.

## Feed row anatomy

Each row in the feed has:

- **Kind chip** (left) — coloured circle with the kind's icon
- **Description** — the activity text
- **Chip row** (below description, when present) — clickable-looking but display-only chips:
  - 🏢 **Account name** — when the activity is tied to an account
  - **DEAL-…** — when tied to a deal
  - **LEAD-…** — when tied to a lead
  - 👤 **Contact name** — when tied to a contact
- **Right column** — actor name on top, relative timestamp below (`47m ago`, `3h ago`, `9d ago`, or full date for older entries)

The chip row is the page's "what does this activity touch?" callout — it tells you which entities to open elsewhere to act on the row.

## Filter the feed

- **Kind pills** — `All` + one pill per kind (System / Email / Call / Meeting / Note / Status), each with a count. Single-select.
- **Counter** on the right: `SHOWING N OF M` for the current filter.

There is no search, no date-range filter, no actor filter.

## What ops *cannot* do on this page

- Create a `System` or `Status` row by hand (only the engine writes those)
- Edit or delete a logged activity
- Click into an activity for a detail drawer (every row is fully self-contained)
- Click the chips to navigate (display-only)
- Reassign an activity to a different account, deal, lead, or contact
- See the full activity history for a single entity from this page — to scope to one account, open it in **[CRM Accounts](/v3/crm/accounts)** and read the **Recent Activity** section in that drawer; same for **[Deal Pipeline](/v3/deal-flow/pipeline)** for a deal

## Where rows come from — the full picture

| Kind | Origin |
|---|---|
| **Note / Email / Call / Meeting** | Admin clicks **+ Log Activity** on this page |
| **System** | Automation rules from **[Automations](/v3/crm/automations)** that fire on app events (configurator save, sell submit, etc.) |
| **Status** | Entity state-machine transitions — a Lot moves through **[Inventory Lots](/v3/supply/inventory)** states, a Demand moves on **[Demand Book](/v3/crm/demand)**, a deal moves through **[Deal Pipeline](/v3/deal-flow/pipeline)**, escrow placements on **[Escrow](/v3/settlement/escrow)**, etc. |

Every entity-state-machine doc in the knowledge base owns its own state definitions; this page just surfaces the transitions in the unified feed. If you need to know what a state means, open the source-of-truth doc (e.g. the lot lifecycle in **[Inventory Lots](/v3/supply/inventory)**).

## Things to know

- **System and Status rows are read-only.** They can only be created by the engine. If you need to "fix" a system row, fix the entity it came from — the entity's state machine will emit a new row.
- **Manually-logged activities are permanent.** There's no edit and no delete. If you typed the wrong description, log a new Note correcting it; the original stays.
- **Account is the only link an admin can set when logging.** The Description carries the rest. The chip row on a future activity will only show the Account chip — there are no Deal / Lead / Contact pickers on the log form.
- **Every log is audited.** A logged activity writes to the Audit Log on **[Platform Audit](/v3/platform/audit)** in addition to landing here.
- **No search.** If you need to find a specific past activity, scope by **Kind** and scan, or open the relevant Account / Deal / Contact and read their per-entity activity sections.
- **Filter counters are total, not filtered.** Each kind pill's count is the count of activities of that kind across all filters — picking a kind doesn't change the others.
- **Status rows reference state machines defined elsewhere.** A `Status` row that says *"Lot moved CLAIMED → SOURCED"* gets its definitions from **[Inventory Lots](/v3/supply/inventory)**, not from this page. Open the source doc to act on the row.
- **Empty state.** When the current filter has no rows, the page shows *"No activities of this kind yet."* with a wave-square icon. Switch the kind filter to see whether activity exists elsewhere.
